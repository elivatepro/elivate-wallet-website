## Installing the CLI

The CLI is a single static binary. Install it the same way you install
the agent — script or manual.

```bash
brew install meridian/tap/cli
# or
curl -sSL https://get.meridian.systems/cli | sh
```

Verify:

```bash
meridian --version
# meridian-cli 1.4.2 · workspace acme-prod · region us-east-1
```

## The five commands you'll actually use

<Tabs>

<Tab title="meridian status">

Print the live state of the local agent — connection, ingest health,
clock skew, and the size of the on-disk buffer.

```bash
meridian status
# connected · ingest=ok · clock-skew=12ms · buffer=8.2 MB
```

</Tab>

<Tab title="meridian pipeline apply">

Push a pipeline file to the control plane. The CLI validates locally
first, then estimates the volume change before the rollout.

```bash
meridian pipeline apply pipelines/api-prod.toml --diff
```

</Tab>

<Tab title="meridian objective check">

Dry-run an SLO definition against the last 24h of data without
publishing it. Useful when you're tuning the threshold.

```bash
meridian objective check ./checkout-availability.toml \
  --window 24h
```

</Tab>

<Tab title="meridian incident list">

List the open incidents for the workspace, with the on-call engineer
and the time since the budget event fired.

```bash
meridian incident list --status open
```

</Tab>

<Tab title="meridian restore">

Pull a slice of cold-tier data back into warm. Returns a job ID; you'll
get a notification (Slack/email) when it's queryable.

```bash
meridian restore --signal traces \
  --service checkout --from 2025-04-01 --to 2025-04-07
```

</Tab>

</Tabs>

## Configuration file

The CLI reads from `~/.config/meridian/cli.toml`. Most teams check this
file into a personal dotfiles repo.

```toml title="~/.config/meridian/cli.toml"
workspace = "acme-prod"
region    = "us-east-1"
format    = "text"

[notifications]
slack = "https://hooks.slack.com/services/..."
```

> **Tip.** The CLI respects `MERIDIAN_*` environment variables, which
> trump the config file. CI systems should rely on env vars; humans on
> the file.
